The loop is the clue.

Fetching a collection is one query. Touching an unfetched relationship for every item adds one query per item.

01 / The trap

One book, one author query

Book.objects.all() loads Books. Accessing book.author.name in a loop can then query the Author table once for each Book.

02 / The decision

Follow the relationship shape

Use select_related() for one-to-one joins. Use prefetch_related() when the related side can return many rows.

03 / The payoff

Make query count predictable

With the right eager loader, the number of database round trips stays steady as your result set grows.

Rule of thumb: select_related uses SQL JOINs for a single related object. prefetch_related runs a separate query and joins results in Python, which supports many-to-many and reverse relationships.
